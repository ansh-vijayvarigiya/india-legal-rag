# Troubleshooting

Environment problems hit while building this, and what fixes them. None of these are project bugs;
they are all properties of this machine or of a dependency.

| Symptom | Cause | Fix |
|---|---|---|
| Repeated `Windows fatal exception: access violation` with an identical PyTorch stack, while tests still pass | `faulthandler` reporting a handled structured exception inside torch's CPU kernels on a hybrid-core CPU | Run `pytest -p no:faulthandler`. A standalone script needs no flag and exits 0. |
| `UnicodeEncodeError: 'charmap' codec can't encode character` printing Devanagari, an en dash or a curly quote | PowerShell's console code page is not UTF-8 | `$env:PYTHONIOENCODING = "utf-8"`, or write output to a file |
| `ImportError: Modest backend is deprecated` from `selectolax` | `selectolax` 1.x removed its old backend | Import `from selectolax.lexbor import LexborHTMLParser` |
| `bash` fails with a WSL distribution error | `bash` on `PATH` resolves to the WSL launcher, and no distribution is installed | Use Git's shell: `C:\Program Files\Git\bin\bash.exe` |
| `Exception ignored in: QdrantClient.__del__` and `ModuleNotFoundError: msvcrt` at exit | `portalocker` cannot import `msvcrt` while the interpreter is shutting down | Harmless, and does not affect the exit code. Call `ChunkIndex.close()` to release the lock deliberately. |
| `recreate()` leaves old points in the index | Qdrant local mode does not persist a collection deletion | Handled inside `ChunkIndex.recreate`, which drops the storage directory. See `decisions.md` D-015. |
| Embedding runs on CPU although the machine has a GPU | The installed PyTorch is the CPU-only build (`2.14.1+cpu`) | Install PyTorch from the CUDA 12.8 wheel index. CPU is acceptable at this corpus size; see `decisions.md` D-006. |
| `warning: LF will be replaced by CRLF` on commit | Git's `core.autocrlf` on Windows | Cosmetic only |
| `python -m legalrag.inspector` prints `missing ScriptRunContext` warnings and serves nothing | A bare module run has no Streamlit runtime; only `streamlit run` sets one up | Handled inside the module, which starts the server itself when it is not already under one. `streamlit run src/legalrag/inspector.py` also works. |
| `python -m legalrag.inspector` appears to hang: no error, nothing served, the last output is `Email:` | Streamlit prompts for an email on first run unless the server is headless, and with no TTY the prompt waits forever | Handled inside the module, which passes `--server.headless=true` when it starts the server. Writing `~/.streamlit/credentials.toml` with an empty `email` also clears it. |
| `LEGALRAG_DATA_DIR` is set, but the index is written to `./data/qdrant` | `Settings.qdrant_path` is its own field and does not follow `data_dir` | Set `LEGALRAG_QDRANT_PATH` as well. Keeping them independent is deliberate (D-001, Task 1), but the two must be moved together. |
| The Answer tab says no AI key is configured | `LEGALRAG_LLM_API_KEY` is unset, so there is no model to ask | Put `LEGALRAG_LLM_API_KEY=...` in a `.env` file in the project root and restart. Search, evaluation and the Passages tab all work without a key. |
| Asking two or three questions in quick succession returns a rate-limit message | The free plan meters roughly 8,000 tokens a minute, and a request carrying five passages is about a third of that | Wait twenty seconds, as the message says. Nothing is broken. A paid plan or a different provider removes the wait. |
| An answer stops mid-sentence | The reply hit its token cap, because a reasoning model spends part of the cap on hidden reasoning | Already handled: `finish_reason == "length"` raises instead of displaying the fragment. Raise `MAX_REPLY_TOKENS` in `answer.py` if it recurs. |
| A citation like `[1]` in an answer points at a passage that does not use it | Models mark citations differently, including full-width `【1】` and `[1†L2-L4]` | `_normalise_markers` rewrites every form to `[1]` before parsing. If a new form appears, add it there. |
| `make judge` prints lines like `q004: not judged` | Either the call failed after its one retry on a rate limit, or the judge's reply was cut off before its JSON. The second is the common one: a judge reasons before it writes, and at the answerer's token budget six of twenty questions came back cut off. | The reason is in `answers.md`, in that question's `Verdict` line. A question that was not judged is excluded from the summary rather than scored, so a failure of this harness is not reported as a wrong answer. If the reason says it was cut off, raise `JUDGE_MAX_TOKENS` in `judge.py`; if it is the quota, raise `--delay`. |
| `make judge` fails with `429 ... tokens per day (TPD): Limit 200000` | A full run costs roughly a hundred thousand tokens across both models, so three or four runs in a day exhaust the free allowance. It is counted per model per day and does not clear on retrying. | Wait for the daily reset, or use `make judge LIMIT=5`. The answers cannot be written without the answerer's quota either, so the run has to stop rather than degrade. |
| `make judge` fails with `429 ... Limit 1000, Requested 1017` | The judge model's free tier meters output tokens per minute at a thousand, and a request whose estimated output exceeds that is refused before it runs at all. Hidden reasoning counts as output. | Reasoning is already off for the judge. Lower `JUDGE_MAX_TOKENS` in `judge.py`. Buying the judge a real thinking budget needs a paid tier; nothing in the request shape can get around the meter. |
| `make judge` stops on the first question with a 429 | The judge retries once after 30 seconds; a second limit in a row is given up on | Raise `--delay` (default 20 seconds) or judge fewer questions per run with `--limit 5`. |
| The inspector starts returning nothing, or errors, right after `make eval` or `make judge` | All three use the same Qdrant directory, and both commands rebuild the index from scratch, dropping the storage directory the running app has open | Restart the inspector, or give one of them its own `LEGALRAG_QDRANT_PATH`. Only one process should hold the index at a time. |
| The Evaluation tab shows numbers that do not match `results.md` | The tab recomputes retrieval from the index the app is holding, so it disagrees when the corpus or the chunking changed after `results.md` was written | That disagreement is the finding, not the bug. Run `make eval` to regenerate `results.md`, then restart the app. If the numbers match, the index is the one the report describes. |
| `Grade this answer` answers with a rate-limit message | The judge model meters output tokens at a thousand a minute, and a hidden reasoning allowance counts as output | Wait about a minute. The answer stays on screen and grading can be retried; the button spends one call per press, not per page load. |
| Pressing `Grade this answer` changes the answer | It should not: answers are cached per question in session state, so grading acts on the text on screen. A new question is a new call by design. | If the text really changes on a repeated press of the same question, the cache is being cleared - check that `st.session_state["answer"]` survives the rerun rather than the keys being rebuilt with new ids. |
| CI fails in `pip install` with `error: incomplete-download` on `triton` or an `nvidia-*` wheel | PyPI's Linux `torch` wheel depends on the CUDA stack, about 2.5 GB of libraries a CPU runner never uses, and one of those wheels truncates at 163.6 MB on this runner every time | Handled in `ci.yml`, which installs CPU torch from the PyTorch CPU index before the project, so the CUDA wheels are never requested. Nothing in this project needs a GPU at test time. |
| The deployed app says no AI key is configured although the secret was added | Secrets belong to the app, not the repository, and a running app does not re-read them | Dashboard, app, Settings, Secrets - top level, no `[section]` header. Then **Reboot app**. A `.env` file will not work: it is gitignored, and the host never sees it. |
